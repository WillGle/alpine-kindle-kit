## Findings, most consequential first

1. Recovery and custom boot remain unproven. A bounded read of boot0 found
   `U-Boot 2009.08-lab126` (hardware report 3175–3179). This is a stored version
   string, not a verified active boot path or unlocked bootloader. Neither root
   access nor block-device ro=0 establishes absence of boot signature checks.
   No full eMMC/boot-area backup or verified restore exists yet. Do not flash.
2. The running kernel explicitly has `CONFIG_KEXEC` disabled (1254). Normal
   kexec handoff is unavailable in this kernel. This does not prove all alternate
   boot paths impossible; U-Boot/recovery access must be investigated separately.
3. The live e-ink module is proprietary: mxc_epdc_eink is loaded with `(P)`
   (235–236). mxc_epdc_fb drives the display. A panel_flash_spi driver is bound
   (685–689); waveform/calibration storage and extraction have not been mapped.
   Do not assume an eMMC backup captures panel SPI data. A new kernel cannot
   simply reuse this old binary module without compatibility work.
4. Stock kernel reuse constrains a new userspace: Linux 3.0.35, ext2/ext3 enabled,
   ext4 disabled; DEVTMPFS disabled; USE_OF disabled. Initrd support is enabled
   but listed gzip/bzip2/lzma/xz/lzo decompressors are disabled. Build a compatible
   userspace only after validating toolchain, libc and device-node provisioning;
   no current distribution image has been established compatible.
5. The collection is useful but not exhaustive. Three harmless `cat` errors
   occurred on I2C adapter directory entries (676/680/684); collection continued.
   Module/firmware enumeration and hashes were depth-limited and can omit deeper
   files. Boot-area reads were limited to the first MiB and exported version
   matches only. Boot environment, boot ROM security/fuses, full startup contents,
   panel data and recovery execution were deliberately not collected. No claim
   of complete firmware integrity or complete hardware inventory is warranted.

are fitted. RAM free values are a snapshot, not a minimum OS memory requirement.

| boot0 | separate | 4 | U-Boot version string found |
| boot1 | separate | 4 | No version match in bounded scan; not proven empty |

Main user area: 7634944 sectors × 512 = 3909091328 bytes (3728 MiB).
A whole-device image cannot fit into its own user partition. A recovery backup
needs off-device transport and a consistency strategy for writable filesystems.

## System inspection cross-check

The root ext3 mount is read-only; /var/local and user storage are writable.
OTA executable backups otaupd.bck and otav3.bck remain present, their Upstart jobs
were stopped. No captured TCP listener on 22 or 8080. The `sshd start/running`
job label is not evidence of a listening SSH server. Other listeners exist;
ownership beyond UID and purpose were not established. No clean-stock or
malware-free conclusion follows from this inspection.

## Readiness decision

Enough evidence now exists to scope a Linux replacement feasibility plan, but
not to select a flashable image or perform OS replacement. The next gate is a
model-specific, documented and tested recovery/custom-boot route, together with
consistent off-device backups including identified panel data. An independent
userspace on a compatible vendor kernel is a possible intermediate direction,
not proof of independence from all vendor code. Full kernel replacement requires
separate display, touch, Wi-Fi and power support validation.

This review changed only local evidence/docs. No device configuration changed.
