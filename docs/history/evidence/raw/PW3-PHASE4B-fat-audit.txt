PW3 Phase 4B — p4/FAT integrity audit and repair
Date: 2026-10-31 local
Backing: /dev/mmcblk0p4, exported as /dev/sda1 (FAT32, label Kindle)
Mount at rescue: /run/media/will/Kindle

1. Direct host fsck attempt while unmounted
   Command: fsck.vfat -n -v /dev/sda1
   Result: "open: Permission denied" (host user lacks raw block-device access)
   This is an access limitation, not a filesystem result.

2. UDisks2 privileged check before repair (read-only)
   Method: org.freedesktop.UDisks2.Filesystem.Check
   Object: /org/freedesktop/UDisks2/block_devices/sda1
   Result: (false,)
   UDisks2 defines the boolean as "whether the filesystem is undamaged".
   Therefore this was a real inconsistency finding, not a clean result.

6. Context
   The host kernel had warned "Volume was not properly unmounted. Some data may
   be corrupt. Please run fsck." after a USB reset during a rescue token write.
   The device did not boot Alpine; it re-enumerated as rescue and retained all
   images. The inconsistency was therefore contained and repaired.

7. Limits
   - UDisks2 returns only a boolean, not the underlying fsck.vfat transcript.
   - FAT remains unjournaled. A successful repair does not prove crash
     consistency or protect against eMMC/FAT corruption.
   - The full control tree backup is retained on the host.
